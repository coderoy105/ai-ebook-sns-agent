# Codex OAuth Worker

Persistent process for AI BOOK STUDIO's ChatGPT-managed Codex authentication and GPT-5.6 Luna execution.

## Why this is separate from Vercel

Codex App Server owns the ChatGPT OAuth credential lifecycle and persists credentials under `CODEX_HOME`. A long-lived worker with persistent storage is therefore required; Vercel Functions only authenticate the AI BOOK STUDIO user and forward signed requests.

## Required environment

- `CODEX_WORKER_SHARED_SECRET`: random secret, at least 32 characters. Must exactly match the Vercel server-only value.
- `CODEX_DATA_ROOT`: persistent volume root. Defaults to `/data/codex-users`.
- `PORT`: defaults to `8787`.
- Optional `CODEX_WORKER_CLOCK_SKEW_MS`, `CODEX_WORKER_IDLE_MS`.

Mount a persistent volume at `/data`. Never mount this directory into the public web container and never copy it into CI artifacts.

## API

All endpoints except `/health` require HMAC headers generated by `lib/ai/codex-worker.ts`.

- `POST /auth/start` — starts `account/login/start` with `type: chatgptDeviceCode` and immediately returns `loginId`, `verificationUrl`, `userCode`.
- `GET /auth/status?userId=...` — uses `account/read`, `model/list`, and `account/rateLimits/read`.
- `POST /auth/logout` — calls `account/logout`, stops the user's App Server process, and removes that user's CODEX_HOME.
- `GET /models?userId=...` — returns the real App Server model catalog and whether `gpt-5.6-luna` is present.
- `GET /usage?userId=...` — returns the supported rate-limit snapshot without guessing model-to-bucket mappings.
- `POST /generate` — verifies that `gpt-5.6-luna` is actually present, then drives `thread/start` + `turn/start` and consumes `item/agentMessage/delta`, token-usage, and `turn/completed` notifications.

## Isolation and secrets

The worker validates UUID user IDs, hashes them before deriving a filesystem path, uses `0700` user directories, never returns OAuth access/refresh tokens, never stores OAuth credentials in Supabase, rejects replayed signed requests, and disables network/tool access for book-writing turns.

## Hosting

Build this directory as a Docker service and attach persistent storage. The service must be reachable from Vercel over HTTPS. Do not expose the service without an HTTPS reverse proxy / managed TLS endpoint.

The current ChatGPT environment has GitHub, Vercel, and Supabase connections but no connected persistent-container hosting provider, so repository code can be prepared here but the worker cannot be truthfully marked deployed until a persistent host is connected.
